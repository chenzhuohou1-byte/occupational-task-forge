## 1. 判分器命令行接口契约（MUST）

### 1.1 命令行

```
score_outputs.py --output <产出目录> --reference <隐藏答案目录> [--variant <变体名>]
```

- 两个参数**必填**，名字**固定**，不允许 `--pred-dir` / `--gt-dir` / `--agent` 之类同义词。
- 脚本必须能**离线重跑**：只要有这两个目录，不依赖网络、不依赖虚拟机、不依赖运行顺序。
- 变体任务（一个 `evaluate()` 服务多个实例）用 `--variant` 区分，而不是加新 flag。

### 1.2 输出 JSON schema（stdout）

```json
{
  "score": 0.87,
  "passed": false,
  "errors": [],
  "details": [
    {"path": "items.BG-05", "expected": "-103200", "observed": "0", "correct": false}
  ],
  "missing_paths": ["items.BG-05"],
  "extra_paths": [],
  "meta": {"scorer": "score_outputs.py", "version": "0.1", "mode": "numeric"}
}
```

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `score` | ✅ | float | 归一化到 `[0.0, 1.0]`。**不是百分制**；百分制要在脚本内除完再输出 |
| `passed` | ✅ | bool | 是否通过。**采用 ALE 主流命名 `passed`，不用 `pass_fail`** |
| `errors` | ✅ | string[] | 判分器自身认为的致命问题；非空时 `score` 必须为 0 |
| `details` | ✅ | object[] | 逐项明细，每项 `{path, expected, observed, correct}` |
| `missing_paths` | ⬜ | string[] | 应交付而未交付的条目 |
| `extra_paths` | ⬜ | string[] | 多交付的条目 |
| `meta` | ⬜ | object | 判分器版本、模式、随机种子等，便于复现 |

**硬约束：**
- stdout **只能有一个 JSON 对象**。日志一律走 stderr。禁止 `print("scoring...")` 污染 stdout。
- `score` 与 `passed` **必须同时给**，且二者语义不同：`score` 是连续分（用于排名/部分分），`passed` 是二元结论（通常远严于 `score >= 阈值`）。ALE 里 `financial_stmt_reconstruction_aapl_fy2024` 就是这个范式：`score` 给部分分，但 `passed` 要求 `accuracy >= 0.95` **且**三个总额全对。

### 1.3 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 判分正常完成。**agent 交了 0 分产物也必须返回 0**，通过 `score=0.0` 表达 |
| 非 `0` | 判分器自身故障（答案目录缺失、依赖装不上、判分脚本崩溃） |

**铁律：agent 产物不对 ≠ 判分器故障。** 前者返回 0 分，后者才抛异常。ALE 用 `JudgeInfrastructureError(RuntimeError)`（`tasks/utils/evaluation.py:20`）做这个区分，我们照抄这个设计。

### 1.4 六条铁律

1. **不写 `output/`**：判分器只读不写产出目录（论文 Appendix C.3.1 明文要求）。
2. **不改 `input/`**：输入素材只读。
3. **产物缺失/形状不对 → 返回 0 分，不抛异常**：超时或拒答的 agent 也要拿到一个良定义的数字。
4. **隐藏答案缺失 → 提前返回 0.0**：`evaluate()` 开头先列必需的参考文件路径，缺一个就返回，不要跑一半崩掉。
5. **stdout 纯净**：只有一个 JSON。
6. **可离线重跑**：同一对 `--output/--reference` 必须得到同一个 `score`（除非显式声明随机性并固定种子）。

## 2. 任务卡 `evaluation` 字段 schema（MUST）

ALE 的历史债：165 张卡里 **154 张的 `evaluation` 是一段散文**，只有 **2 张**是结构化对象（`engineering/2d_drawings_to_3d_building_model` 与 `..._bridge_model`），另有 **9 张完全缺失**。
**我们不继承这个债：一上来就规定必须结构化。**

```json
"evaluation": {
  "type": "numeric_tabular",
  "artifactModes": ["structured_tabular"],
  "composition": ["gate_and_score", "weighted_rubric"],
  "locale": "host",
  "scorer": "scripts/score_outputs.py",
  "passThreshold": 0.95,
  "passRule": "all key totals exact AND accuracy >= 0.95",
  "hardGates": [
    "output/report.xlsx 存在且可解析 -> 否则 0.0",
    "必需字段齐全（11 项）-> 缺任一项 0.0",
    "条目集合与参考集合一致 -> 不一致 0.0"
  ],
  "tolerance": {
    "mode": "relative",
    "value": 0.001,
    "rationale": "金额类，取行业惯例 0.1%；见 §4.1"
  },
  "weights": {
    "fieldAccuracy": 0.8,
    "flaggedSet": 0.2
  },
  "fixtureScores": {
    "output_test_pos": {"expected": 1.0, "observed": null},
    "output_test_neg": {"expected": 0.0, "observed": null}
  }
}
```

| 字段 | 必填 | 取值 |
|---|---|---|
| `type` | ✅ | 判分范式标签，自由字符串但需在团队词表内 |
| `artifactModes` | ✅ | 取自论文 7 类：`exact_hashed` / `structured_tabular` / `geometric_spatial` / `visual_appearance` / `behavioral_world_state` / `free_text_semantic` / `executable_artifact` |
| `composition` | ✅ | 取自论文 4 类：`gate_and_score` / `weighted_rubric` / `binary_checklist_averaging` / `pairwise_file_aggregation` |
| `locale` | ✅ | `host` / `vm`。**默认 `host`**，理由见论文 C.3.1：判分代码更易审阅、纳版本管理、可离线重跑 |
| `scorer` | ✅ | 相对任务目录的脚本路径 |
| `passThreshold` | ⬜ | 归一化阈值。无阈值（纯连续分）时省略 |
| `passRule` | ⬜ | 人类可读的通过条件，当它比单一阈值复杂时必填 |
| `hardGates` | ✅ | 字符串数组，**逐条写清"什么情况 → 0.0"**。无闸门时给空数组，不许省略 |
| `tolerance` | ✅ | 见 §4.1。**这是 ALE 的空白，我们必须填** |
| `weights` | ⬜ | 加权 rubric 时必填 |
| `fixtureScores` | ✅ | 出题人自证义务，见 §2.1 |

### 2.1 `fixtureScores`：出题人的自证义务

每条任务**必须**提供两个夹具目录，且预期分写进任务卡：

- `fixture_pos/`：标准答案原样提交 → 判分器必须给出 **1.0**
- `fixture_neg/`：刻意做坏的答案 → 判分器必须给出 **0.0**

> 相对 ALE 的改进：ALE 只在 2 张结构化卡里写了 `fixtureScores`（且是描述字符串，如 `"1.0 (8/8 YES — ...)"`）。我们要求**机器可校验**：`expected` 是数字，`observed` 由自测脚本回填，`observed != expected` 直接判为判分器不合格。

## 3. 三份判分器模板

三份模板都在 `交付物2_templates/`，均可直接运行：

| 模板 | 文件 | 适用产物 | 对应 ALE 代表任务 |
|---|---|---|---|
| 数值型 | `score_numeric.py` | 多字段数值/表格，逐字段比对 | `business_finance/financial_stmt_reconstruction_aapl_fy2024` |
| 集合型 | `score_set.py` | 清单/集合，先比集合再比条目 | `agriculture_env/crop_rotation_d02` |
| 定性型 | `score_qualitative.py` | 结构化 JSON 的定性结论 + 证据回溯 | `computing_math/k8s_payment_api_root_cause_analysis` |

### 3.1 数值型骨架

```
1. 文件不存在        -> score 0.0 / passed False / errors[...]，不抛异常
2. 递归压平 JSON     -> {"assets.current.cash": Decimal("29943")}
3. 逐字段比对        -> accuracy = correct / total            ← 部分分在这里
4. passed 另算       -> 关键总额全对 AND accuracy >= passThreshold
5. 输出 details / missing_paths / extra_paths
```

关键：**分数给部分分，`passed` 卡关键项**。这个"松紧分离"是四条 ALE 任务里最一致的设计。

### 3.2 集合型骨架

```
闸门（不过则整题 0，不给部分分）：
  - 文件存在且可读
  - 结构/列名/坐标系/图层名精确匹配
  - 主键列存在、非空、唯一
  - ★ 主键集合与参考集合完全一致（筛多了或筛漏了 -> 0）
算分（过闸门后）：
  - Σ(每字段权重 × 该字段逐行精确匹配率)        ← 部分分在这里
  - + 集合条数分（全有或全无）
  - + 集合 ID 分（全有或全无）
```

关键：**「该有哪些条目」是闸门，「每个条目的值对不对」才是分数。**
→ 直接对应 TODO 里造价第 7 条之外的 **BG-05 漏报项**：没识别出漏报项应当**整题 0**，而不是扣 1/11。

### 3.3 定性型骨架（重点）

```
闸门：
  - 输出是合法 JSON
  - 必需顶层 key 齐全
  - 结论列表非空
算分（加权）：
  - 分类标签命中（关键词归一化 + 正则）          权重最高
  - 严重度/金额档位判对
  - 集合类分项用 F1（识别出几个、多识别了几个）
  - 整改措施用正则命中计数
  - ★ evidence 逐字回溯：每条证据必须能在输入材料里原样找到
    missing = [e for e in evidence if not any(e in t for t in input_texts)]
    有一条找不到 -> 该条结论整个不算 grounded
```

关键：**`item in text` 一个子串检查，就把"模型有没有瞎编证据"变成机械可判。**
定性型答复的字段设计建议（对应造价司法鉴定意见书）：每条争议焦点一个对象，含
`类型标签 / 金额影响 / 责任方 / 依据条款 / 证据原文`。

## 4. 容差与权重怎么定（补 ALE 的空白）

TODO 第六节坑 3 指出：**ALE 的权重和容差全是逐任务拍的，论文没给选取准则**（如某任务用 1% 相对误差、某任务用 0.70/0.30 双阈值加权）。这是我们必须补的空白。

### 4.1 容差：四档 + 选择流程

| 档位 | `mode` | 适用 | 例 |
|---|---|---|---|
| **精确** | `exact` | 标识符、分类标签、哈希、计数、集合成员 | 图层名、`id_lcp`、状态码 |
| **绝对** | `absolute` | 物理量，量纲固定且绝对值有意义的 | 坐标 `±0.001 m`、温度 `±0.1 K` |
| **相对** | `relative` | 金额、规模随数量级变化的量 | 造价金额 `0.1%` |
| **分档** | `banded` | 连续质量分，按阈值分档给部分分 | `0.70·frac_within(0.3mm) + 0.30·frac_within(2.0mm)` |

**选择流程（按顺序问，第一个"是"就停）：**
1. 这个值**能枚举**吗（标签/ID/计数/哈希）？→ 是 → **精确**
2. 它**有固定量纲且量级稳定**吗？→ 是 → **绝对**
3. 它**随数量级伸缩**（金额、比例、规模）？→ 是 → **相对**
4. 以上都不是，且**越接近越好、允许渐进给分**？→ 是 → **分档**

**容差的依据必须写进 `tolerance.rationale`**，不许裸写一个数字。可接受的依据来源：
行业规范 / 参考实现的数值精度 / 输入数据的有效位数 / 出题人实测的噪声水平。

### 4.2 权重：三档 + 选择流程

| 档位 | 适用 |
|---|---|
| **等权** | 各分项重要性相当，且没有"必须命中"的核心项。最省事，优先选它 |
| **核心项加权** | 存在 1~2 个"命中才是这道题考点"的分项，给 2~3 倍权重，其余等权 |
| **专家定权** | 仅当上述两档都明显不合适时使用。**必须附 QC 说明**，并在任务卡 `weights` 里显式列出 |

**原则：能用闸门表达的，不要用权重表达。**
一个分项如果是"不做对就等于没做这道题"，它应该进 `hardGates`（不通过直接 0），而不是拿一个高权重。
ALE 的 `gate-and-score` 就是这个思想：`manufacturing/gcode` 里 PowerMill 碰撞/过切闸门不过，几何相似度再高也是 0。

### 4.3 决策表

| 你的情况 | 容差 | 权重 |
|---|---|---|
| 标签/ID/集合成员 | 精确 | 等权 + 集合一致做闸门 |
| 金额/造价 | 相对 0.1% | 核心项加权（总额类做闸门） |
| 物理量（几何/坐标） | 绝对，按有效位数 | 分档 |
| 定性结论 | 精确（标签）+ 档位（严重度） | 核心项加权 |
| 连续质量分 | 分档 | 专家定权 + QC 说明 |

## 5. 什么时候必须用大模型（MUST）

沿用论文 C.3.4 的standing rule，并作为我们的强制条款：

1. **产物能机械校验的，不许用大模型判。**
   论文原文：`if the deliverable can be reduced to bytes, fields, geometry, world state, or executable behavior, the scoring code must operate on those signals, not on a model's holistic opinion.`
   提案「问模型这个结果看起来对不对」的任务，质检阶段直接打回。ALE 实测比例：**纯代码判分 93.2%，大模型仅 6.8%**。
2. **大模型只许回答二元 YES/NO 问题**，且每问只针对一个具体可辨识的对象（"左上角有没有橙色圆形"，而不是"这个交付物好不好"）。
3. **多数探针直接写成硬闸门**：不相关的产物在任何质量判断之前就 0 分。
4. **其余一律问「够不够过」**（`... enough to pass?`），把模型变成"同/不同"比较器，而不是自由裁量的质量裁判。
5. **加权、gating、汇总永远在代码里做。大模型不做汇总。**
