### 2.2 四个角色的职责边界

| 角色 | 文件 | 只负责 | 绝不负责 |
|---|---|---|---|
| **外层调度** | `main.py` 的 `evaluate()` | 检查答案在不在、跑脚本、取分数 | 判分逻辑 |
| **判分器** | `scripts/score_outputs.py` | 闸门 + 算分 + 打 JSON | 写 `output/`、改 `input/`、抛异常 |
| **任务卡** | `task_card.json` 的 `evaluation` | 声明闸门、阈值、容差、权重、正负例预期分 | 存散文描述 |
| **夹具** | `fixture_pos/` `fixture_neg/` | 证明判分器真的能区分对错 | 参与正式判分 |

### 2.3 一条铁律：闸门与部分分的位置

```
「该有哪些条目 / 格式对不对 / 集合一致吗」  →  硬闸门，不给部分分，不过就是 0
「每个条目的值算得对不对」                  →  连续分，给部分分
```

**这条决定了 BG-05 漏报项的口径**：agent 没识别出漏报项 → **整题 0 分**，而不是扣 1/11。
因为"发现漏报"正是考点，识别不出来等于没做这道题。

## 三、关键代码

### 3.1 契约的唯一出口 —— 所有 return 都走这里

```python
def report(score=0.0, passed=False, errors=None, details=None,
           missing_paths=None, extra_paths=None, **extra) -> dict:
    """统一的输出形状。所有 return 都走这里，保证 schema 一致。"""
    out = {
        "score": float(score),
        "passed": bool(passed),
        "errors": list(errors or []),
        "details": list(details or []),
        "missing_paths": sorted(missing_paths or []),
        "extra_paths": sorted(extra_paths or []),
        "meta": {"scorer": Path(__file__).name, "mode": "numeric",
                 "tolerance": TOLERANCE["mode"]},
    }
    out.update(extra)
    return out
```

> **为什么值得抄**：判分器里会有十几个 return 分支，任何一处漏字段都会让下游解析失败。
> 统一出口是最便宜的防错手段。

### 3.2 产物不对 → 0 分，不抛异常（六条铁律之一）

```python
    # --- 第 1 步：文件不在 -> 0 分，不抛异常 ---------------------------------
    submission_file = args.output / SUBMISSION
    answer_file = args.reference / ANSWER
    errors = []
    if not submission_file.is_file():
        errors.append(f"missing required output: {SUBMISSION}")
    if not answer_file.is_file():
        errors.append(f"missing reference: {ANSWER}")
    if errors:
        print(json.dumps(report(0.0, False, errors), ensure_ascii=False))
        return 0
```

> **为什么重要**：超时或拒答的 agent 也要拿到一个良定义的数字，而不是让整条流水线崩掉。
> ALE 用 `JudgeInfrastructureError(RuntimeError)` 把「agent 产物不对」和「判分器自己坏了」分开。

### 3.3 数值型：压平成「路径 → Decimal」，逐字段比对

```python
def flatten(obj, prefix: str = "") -> dict:
    """{"assets": {"current": {"cash": 29943}}}  ->  {"assets.current.cash": 29943}"""
    out: dict = {}
    if isinstance(obj, dict):
        for k, v in obj.items():
            out.update(flatten(v, f"{prefix}.{k}" if prefix else str(k)))
    elif isinstance(obj, (list, tuple)):
        for i, v in enumerate(obj):
            out.update(flatten(v, f"{prefix}[{i}]"))
    else:
        out[prefix] = obj
    return out
```

**松紧分离**——分数给部分分，`passed` 卡关键项：

```python
    accuracy = correct / total if total else 0.0

    # --- 第 4 步：passed 另算（关键项 + 阈值）--------------------------------
    key_ok = all(d["correct"] for d in details
                 if d["path"].split(".")[-1] in KEY_FIELDS)
    passed = (not errors) and key_ok and accuracy >= PASS_THRESHOLD
```

> `score` 与 `passed` 是**两个不同的东西**：前者是连续分（排名/部分分），后者是二元结论（通常远严于 `score >= 阈值`）。
> ALE 的 Apple 财报那条就是这个范式：`score` 给部分分，但 `passed` 要求 `accuracy >= 0.95` **且**三个总额全对。

### 3.4 集合型：★ 集合一致是闸门，不给部分分

```python
    # ★ 本模板的核心闸门：集合必须完全一致（筛多了或筛漏了 -> 0）
    sub_set, ref_set = set(sub_ids), set(ref_ids)
    missing_ids = sorted(ref_set - sub_set)
    extra_ids = sorted(sub_set - ref_set)
    if not gate("id_set_matches", sub_set == ref_set,
                f"missing={missing_ids} extra={extra_ids}"):
        print(json.dumps(report(0.0, False,
                                ["id set does not match reference"],
                                gates=gates, missing_paths=missing_ids,
                                extra_paths=extra_ids), ensure_ascii=False))
        return 0
```

过了闸门才逐字段给部分分：

```python
    for f, w in FIELD_WEIGHTS.items():
        hit = 0
```

### 3.5 定性型：★ 证据逐字回溯（反幻觉，核心只有几行）

```python
def evidence_grounding(findings, input_texts):
    """每条 evidence 必须是输入材料里的**逐字原文**（不是文件名引用）。
    有一条找不到 -> 这条结论整个不算 grounded。"""
    if not findings:
        return 0.0, []
    grounded = 0
    detail = []
    for f in findings:
        ev = f.get("evidence") or []
        if isinstance(ev, str):
            ev = [ev]
        bad = [e for e in ev if not any(str(e) in t for t in input_texts)]
        ok = bool(ev) and not bad
        grounded += int(ok)
        detail.append({...})
    return grounded / len(findings), detail
```

> **一个 `item in text` 的子串检查，就把"模型有没有瞎编证据"变成了机械可判。**
> 这是整个规范里最便宜、最有效的一行设计。

### 3.6 容差判定 —— ALE 没给准则，我们给了四档

```python
def within(observed: Decimal, expected: Decimal) -> bool:
    """按 TOLERANCE 判定是否算对。"""
    mode = TOLERANCE["mode"]
    if mode == "exact":
        return observed == expected
    if mode == "absolute":
        return abs(observed - expected) <= Decimal(str(TOLERANCE["value"]))
    if mode == "relative":
        if expected == 0:
            return observed == 0
        return abs(observed - expected) / abs(expected) <= Decimal(str(TOLERANCE["value"]))
    raise ValueError(f"unsupported tolerance mode: {mode}")
```

**选档流程（按顺序问，第一个"是"就停）：**

| 顺序 | 问题 | 是 → |
|---|---|---|
| 1 | 这个值**能枚举**吗（标签/ID/计数/哈希）？ | **精确** `exact` |
| 2 | 它**有固定量纲且量级稳定**吗？ | **绝对** `absolute` |
| 3 | 它**随数量级伸缩**（金额、比例、规模）？ | **相对** `relative` |
| 4 | 以上都不是，且**越接近越好、允许渐进给分**？ | **分档** `banded` |

**容差的依据必须写进 `tolerance.rationale`，不许裸写一个数字。**

### 3.7 外层 `evaluate()` —— 只做三件事

```python
async def evaluate(task_cfg, session):
    # ① 隐藏答案在不在？不在就返回 0，不跑判分
    required = [reference_files...]
    if not all_present(required):
        return [0.0]
    # ② 跑判分脚本
    result = await run_scorer(session, "--output", ..., "--reference", ...)
    # ③ 取 score
    return [float(result["score"])]
```

## 五、为什么要"我们自己定"，而不是"沿用 ALE"

**因为 ALE 的接口根本不统一——这是实测结论，不是推测。**

| 概念 | ALE 内部实际用过的 flag（出现次数） |
|---|---|
| 产出目录 | `--output-dir`(36)、`--output`(14)、`--agent`(14)、`--submission-dir`(7)、`--out`(7)、`--candidate-dir`(4)、`--agent-dir`(4)… |
| 答案目录 | `--reference-dir`(37)、`--reference`(19)、`--reference-file`(8)、`--ref`(6) |

| 输出 JSON 的键 | 出现次数 |
|---|---|
| `score` | 219 |
| **`passed`** | **103** |
| `details` | 41 |
| `errors` | 21 |
| **`pass_fail`** | **仅 12** |

**同一概念至少 9 种命名。** 论文承诺的"统一契约"其实只指一件事：
> VM 侧脚本通过 **stdout JSON** 通信、**绝不写 `output/`**。

**所以这份规范不是"沿用 ALE"，而是"把 ALE 想做但没做到的事做到"——这恰恰是我们相对 ALE 的增量价值。**

### 差异一览（对外沟通用）

| 维度 | ALE 现状（实测） | 我们的规范 |
|---|---|---|
| `evaluation` 字段 | 154/165 是散文，2 结构化，9 缺失 | **一律结构化** |
| 判分器 CLI | 至少 9 种 flag 命名 | **固定 `--output / --reference`** |
| 通过键名 | `passed`(103) 与 `pass_fail`(12) 混用 | **统一 `passed`** |
| 容差 | 逐任务拍，论文无准则 | **四档 + 选择流程 + 必须写依据** |
| 权重 | 逐任务拍，论文无准则 | **三档 + "能用闸门就别用权重"** |
| 正负例自证 | 仅 2 张卡写了，且是描述字符串 | **机器可校验的 `fixtureScores`** |
| 大模型占比 | 6.8% | 沿用同一原则，并写进强制条款 |

## 六、大模型的使用边界（强制条款）

1. **产物能机械校验的，不许用大模型判。**（论文原文：`if the deliverable can be reduced to bytes, fields, geometry, world state, or executable behavior, the scoring code must operate on those signals, not on a model's holistic opinion.`）
2. 大模型**只许回答二元 YES/NO 问题**，且每问只针对**一个具体可辨识的对象**。
3. **多数探针直接写成硬闸门**——不相关的产物在任何质量判断之前就 0 分。
4. 其余一律问**"够不够过"**（`... enough to pass?`），把模型变成"同/不同"比较器。
5. **加权、gating、汇总永远在代码里做。大模型不做汇总。**

## 七、需要拍板的两件事

1. **`locale` 保留 `host / vm / both` 三档，还是按主路径归并成两档？**
   建议保留三档——`both` 在我们的场景里会真实出现（数值判分在宿主做，但计量不确定度评定需要专用软件在隔离环境跑）。
2. **容差档位是否认可 §3.6 的四档划分与选择流程？** 这是 ALE 论文留下的空白，也是本规范唯一"没有先例可抄"的部分。
