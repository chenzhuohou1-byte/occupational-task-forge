# 协作者指南 · 边界与分工（本文定“什么必须统一、什么你自己定”）

> 唯一判分权威是 [`判分契约_v1.0.md`](../判分契约_v1.0.md)；上手步骤见 [`CONTRIBUTING.md`](../CONTRIBUTING.md)；
> 表格类操作流程见 [`新增一条数据-playbook.md`](新增一条数据-playbook.md)。
> **本文不重述契约条款**（重述必然漂移），只回答一个问题：多人并行造数据时，
> 哪一层不许各自改、哪一层由领域负责人自己决定。

## 1. 为什么需要这份文档

分工是**按领域**切的（谁负责哪些职业/子域），但代码复用**不按领域走**，按**工具链**走。
实证：`G1`（BPMN 治理）、`E1`（BIDS 容器）、`H3`（PhysioNet ECG）三条题领域互不相干，
但 `pipeline/executable/` 的 runner、适配器、N6/N8、N7 **一行未改**就复用了；真正不同的只有
取数、判据口径、golden/oracle、case 与负例设计。

反过来，一个人的 10 条题常常只落在 2 类工具链上（例：H1–H3 信号影像、H4–H10 表格核算），
而同一类工具链又横跨多人。所以：

- **按领域分管线分支** → 验收语义被复制 N 份，各自漂移，闸门会悄悄失效；
- **按工具链分领域包** → 复用自然发生，纪律只有一份实现。

## 2. 必须统一（不可分叉，改动走框架仓 PR + 评审）

以下属于**数据集完整性**，不是代码风格问题。500 条题的难度数字要能横向比较、坏题要被同一道
闸门拦住，就不能有第二套实现：

| 层 | 具体内容 |
|---|---|
| 判分契约 | `判分契约_v1.0.md` 全文。改契约只改这一个文件，并在变更记录追加依据 |
| 执行编排 | `pipeline/executable/runner.py`：交付齐全检查 → 真实工具链执行 → 逐 case 聚合 → 自报交叉核对 |
| 适配器接口 | `pipeline/executable/engines/base.py` 的 `probe / deploy / run_case / teardown` 与 `EngineUnavailable` |
| 质量闸门 | `pipeline/qc.py` 的 N6 / N8（含可执行分支）、`difficulty_tier` |
| 测量口径 | `n7_run.py` + `pipeline/agentsolve.py`：`model / toolset / budget / scorerVersion / nRuns` 五项齐全才算一条测量 |
| 退出码纪律 | agent 侧问题 exit 0 记分；基建故障 exit 2 + `fault` 记测量故障 |

### 2.1 五条铁律（任何领域包都不得放松）

1. **不信任自报。** 候选交的运行结果必须被独立重算并交叉核对；任一方向不一致 = 报告完整性缺陷，整题判负。
2. **标准答案不进候选执行环境。** 容器类走 `task_meta.host_scorer`（expected 留宿主侧）；候选只拿到当前 case 的输入。
3. **空交付与地板必须是 0。** 空交付、同结构假答案、结构合法但无实质计算的程序，都不得拿到有效分。
4. **故障 ≠ 不会做。** 引擎/容器不可达、网关超时、协议噪声、预算耗尽一律记测量故障，不得记成模型低分。
5. **判分器改了就重测。** 同步改 `evaluation.scorerVersion`，旧 `measuredDifficulty` 即刻作废。

### 2.2 难度只是标签，不是进库门槛

`tier` 由 `measuredDifficulty` 机器派生，**不许手写**。便宜档能满分就是 L1 数据，不因“太软”淘汰；
但**未测 ≠ L1**，定不出级就不进库。前沿档要切 10%/30% 两刀，`nRuns` 不足 10 只能给推定级。

### 2.3 禁止的“加难”手段

删定义、留歧义、藏必要条件、附件截断、工具缺失、预算不足、故障充数——这些制造的不是职业能力难度。
前提恒定：**材料完整、规则明确、任务可解。**

## 3. 由你自己决定（领域负责人自治，不必对齐别人）

- 取数与冻结脚本怎么写、放哪；
- 判据口径文档（协议/契约文件）的组织方式与粒度；
- golden 实现与 oracle 实现的技术选择；
- 隐藏 case、负例矩阵、扰动类型的设计；
- 宿主侧判分语义与 `extra_checks` 的专业逻辑；
- **要不要复用别人的领域包**——不合适就自己写，不必迁就现有抽象。

抽取公共代码的时机：**同类工具链出现 2–3 条题、共同模式真的浮现之后**再抽，不提前设计。
几个人各自写表格判分本身不是问题，只要都过同一套闸门；真正的风险只在闸门语义分叉。

## 4. 领域包（按工具链分，不按职业分）

建议起步只收敛成四类，覆盖面已够：

- **表格核算**：pandas/CSV/xlsx，服务会计、公共卫生、经济社科、体育等；
- **容器执行程序交付**：`docker run --network none` + 隐藏 case，服务数据工程、信号审计等；
- **真实引擎执行**：Flowable 等有状态引擎，服务流程治理；
- **信号与影像**：WFDB/nibabel/MNE/scipy，服务计算神经与实验心理。

一个包应当提供（但都可被领域负责人替换）：取数与冻结、oracle 模板、case 生成器、判分辅助、许可声明模板。
**包可以换，内核与闸门不能换。**

## 5. 两条范式的选择

- **要在真实工具链上跑起来才算完成** → `executable_artifact`（契约 §9.5）。交付可执行产物，
  判分器部署执行、从运行状态独立重算。参考实现：`G1`（flowable 适配器）、`E1`/`H3`（container 适配器）。
- **只需核算出一组数** → `numeric_tabular`。走八节点与四档夹具，判分走逐字段比对 + 硬闸门。

可执行范式的夹具不是四档表格，而是 `assets/reference/golden/output/` 与
`assets/reference/negatives/<name>/output/` + `manifest.json`（标 `target_check` / `faked_results` / `floor`）。
启用 `selfReportCrossCheck` 时**必须**有一条 `faked_results: true` 的负例，证明交叉核对真能抓住它。

## 6. 提交与仓库边界

```bash
python3 tests/run_all.py     # 全绿才提 PR；不花钱、不触网
```

- **框架改动** → 本仓，开分支 + PR + 1 评审，main 不直推；
- **任务数据** → 私有数据仓 `occupational-task-forge-data`，本仓 `tasks/` 已被忽略且钩子拦截；
- 数据仓推送前先 `git fetch` + `rebase` 到最新 `main`（它常有别人的新题）；
- 运行证据（golden 结果、N6/N8、隔离探针、构建环境）随题落 `_build/`，便于复核，不进公开仓。

## 7. 开工前自查

- [ ] 认领的子域没和别人撞；`task_id` 全局唯一；任务卡写了 `负责人`
- [ ] 真实源的许可与出处已写进 `provenance`/来源声明；构造数据与真实事实已分开标注
- [ ] 已检索 ALE 公开样题避重，并记下检索快照（不能保证非公开材料零重叠，如实写明）
- [ ] 判据口径全部冻结进 input，且**没有**把标准解法写成操作提纲
- [ ] 标准答案由脚本复算，并经第二实现交叉复算一致后才落盘（绝不手抄）
- [ ] golden 实测 1.0；每条负例被其 `target_check` 拒；地板被否决
- [ ] `qc` 该过的都过；难度两档按统一口径测量，故障如实记为故障
- [ ] 单轮或 `nRuns` 不足时，`tier` 留空并在 `measurementNote` 写明未定级

## 8. 当前已知缺口（别误以为已完备）

- `agent-file-engine` 只做 deployment 生命周期清理，**不构成数据库/进程级安全隔离**；
  独立受限引擎容器待实现，目前只可用于可信参考产物的功能验证。
- 可执行范式**没有**框架级交叉复算工具（表格范式有 `pipeline/crosscheck.py`），双实现比对需自己写。
- B 类取数（下载、校验、SHA256 清单、许可声明）没有标准节点，每题自写。
- ALE 避重检索尚未脚本化。
- 候选容器隔离探针（非 root / 无网络 / 看不到 expected 与 docker socket）未进 `tests/run_all.py`。
