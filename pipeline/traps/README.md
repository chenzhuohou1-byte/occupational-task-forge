# 陷阱模板库：怎么存、怎么选

> 这里存的是**已验证有效的陷阱设计范例**，供 `build-case` 起草规则时参考、模仿、改编。
> 不是机器契约，不参与 crosscheck/qc 任何一道闸门——陷阱是否真的让模型答错，照常要走
> N7 实测（契约 §6.3）。本目录只降低「从零设计一个陷阱」的人工成本。

## 存放规则

- 每个文件对应一个**领域或子域**，文件名 = ALE 子域 id 或自定短名，如 `6.1.md`、`工程造价.md`。
- 文件内按 `## 标题` 分陷阱条目，每条自然语言写清楚，字段不强制、格式不校验——
  **复制粘贴的成本比结构化字段的成本更重要**。
- 建议每条包含（能写多少写多少，不是必填清单）：
  - 这类陷阱长什么样（具体场景、不是抽象分类名）
  - 为什么它对前沿模型有效（已验证过的实测现象，没验证过的标「未验证」）
  - 换个领域怎么套（这条陷阱的「可迁移结构」是什么）

## 怎么选 / 怎么复用

```bash
python3 -m pipeline.cli traps list                 # 列出所有领域文件 + 每条标题
python3 -m pipeline.cli traps show <文件名或子域id>  # 打印该领域全文，供直接读/改
python3 -m pipeline.cli build-case --subdomain 6.1 --trap-ref 工程造价   # 注入该领域陷阱范例到起草 prompt
```

`--trap-ref` 可以引用**任何**领域的文件，不限于当前子域——陷阱的可迁移结构本身就是
鼓励跨领域套用的（这正是「选择复用或不复用」的意思：不复用就不传这个参数，照旧全自动走
通用陷阱菜单）。

## 不是什么

- 不是 `--refs`（那个喂的是真实口径事实，要求逐字核验出处）；这里喂的是**设计思路**，
  模型会参照着改编，不会被要求逐字抄。
- 不保证复用后这题就难。陷阱模板只提升「这题可能有戏」的命中率，最终难度仍由 N7 实测定。
